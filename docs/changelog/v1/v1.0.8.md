# polyfillme v1.0.8 Changelog

**Release Date**: October 2026
**Release Type**: Patch
**Branch**: `release/1.0.8`

---

## Overview

polyfillme is relicensed from MIT to the Apache License 2.0. The repository now carries the full license text, and the README is reorganized around a What's New section backed by per-version changelogs for every release so far. The dev tooling for file headers moves to `@cldmv/fix-headers` 2.2.0 and `@cldmv/configs` 1.2.4. No runtime code changed.

## ⚖️ License

`package.json` `license` changes from `MIT` to `Apache-2.0`, and a `LICENSE` file with the full Apache License 2.0 text is added at the repository root (previously there was no license file). ## 🔧 Dependencies

Both are dev dependencies and affect only the `npm run fix:headers` script, which extends `@cldmv/configs/fix-headers.json`. Only `package.json` and the lockfile changed; no file headers were restamped and the published package is unaffected.

- `@cldmv/fix-headers` `^2.1.1` → `^2.2.0`, in two steps. 2.1.4 ([#60](https://github.com/CLDMV/polyfillme/pull/60)) no longer writes a JavaScript comment into JSON or Markdown files, processes every repeated `--input`, and never walks dependency folders such as `node_modules`. 2.2.0 ([#61](https://github.com/CLDMV/polyfillme/pull/61)) makes `@Last modified by` follow edits to a file's content only, so a run that merely rewrites a header keeps the recorded editor.
- `@cldmv/configs` `^1.2.0` → `^1.2.4` ([#61](https://github.com/CLDMV/polyfillme/pull/61)). The shared fix-headers config now sets `forceAuthorUpdate` and `forceLastModifiedAuthorUpdate` to `false`, so `@Author` keeps the file's creator and `@Last modified by` changes only with real content edits. The 1.2.1 and 1.2.2 releases of that package only changed its own CI.
