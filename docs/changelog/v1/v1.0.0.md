# polyfillme v1.0.0 Changelog

**Release Date**: July 2025
**Release Type**: Initial

---

## Overview

The first version of polyfillme: a CommonJS Node.js module that scans JavaScript files, detects the built-ins and prototype methods they use, and produces polyfill code for everything that is not part of a target ES/ECMA version. This version was never tagged on its own; it is the state of `master` before the project moved to the CLDMV v4 release flow in v1.0.1.

---

## ✨ Features

### Feature scan and polyfill generation

- `polyfillme(options)` resolves `files` (globs via `fast-glob`, or plain file paths), parses each file with `espree`, and walks the AST to collect used features such as `Array.prototype.includes`, `Object.entries` and `Promise`.
- Feature availability per ES version comes from bundled MDN browser-compat data (`src/data/mdn/mdn.es.json`, generated by `npm run build:mdn`). Features that belong to `ecmaVersion` or any earlier version are treated as available.
- `includedPolyfills` removes features the project already ships; `additionalPolyfills` forces extra ones in.
- Polyfill code comes from `polyfill-library` by default, or from the Cloudflare polyfill CDN with `source: "cloudflare"`.
- The output is written to `polyfills.js` (or `filePath`) unless `writeToFile: false` is passed, and the call resolves to `{ polyfills, content, shams, notFound }`.

An early prototype built on `core-js` / `core-js-compat` was removed before this version; the feature data is MDN-only.

## 🧪 Tests

- Jest suites per ES version (`test/es1.test.js` through `test/es2025.test.js`) plus an API test.

## Known issues

- `src/lib/polyfillSources.js` requires `node-fetch`, which is not declared in `package.json`, so loading the module fails with `MODULE_NOT_FOUND` on a clean install. Fixed in [v1.0.1](./v1.0.1.md).
- The README still describes the removed `core-js-compat` integration and a `Promise<string[]>` return value.
